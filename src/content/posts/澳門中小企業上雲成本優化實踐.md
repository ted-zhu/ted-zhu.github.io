# 澳門中小企業上雲成本優化實踐

> 關鍵詞：阿里雲、成本優化、FinOps、BssOpenApi、節省計劃、標籤治理

## 一、為什麼澳門中小企業更要先談成本

澳門中小企業上雲有幾個很現實的特徵：沒有專職運維，更沒有 FinOps，IT 往往由行政、電商或財務同事兼管；收入是 MOP/HKD，雲賬單卻是 USD；「上雲」常常就是買幾台 ECS、開一個 RDS，業務跑起來就不再回頭看。

於是成本失控通常不是某次大失誤，而是慢性漏水：

- 測試機開著忘記關，一跑幾個月；
- 規格「買大一點保險」，CPU 長期個位數利用率；
- 快照、鏡像、未完成的分片上傳堆積經年；
- 公網帶寬按固定帶寬計費，卻只為每天幾小時的峰值買單；
- 賬單明細沒人讀得懂，也就沒人管。

這篇給出一套適合小團隊的成本治理打法：**看得見 → 分得清 → 優得動 → 防得住** 四步閉環，全部基於阿里雲國際站現有能力與 API，不引入額外工具，一個人兼職也能跑起來。

## 二、看得見：把賬單當數據讀

### 2.1 費用 API 是起點

BssOpenApi（端點 `business.ap-southeast-1.aliyuncs.com`）提供賬號自身賬單的結構化查詢：

| API | 用途 |
|------|------|
| `DescribeInstanceBill` | 實例級賬單主力接口；`IsBillingItem=true` 可下鑽到計費項 |
| `QueryAccountBill` | 賬號級月度匯總 |
| `QueryBillOverview` | 按產品維度的月度總覽 |

三個注意事項：當月數據會延遲與修正，**只做監控、不做結算**（終版次月初）；分頁為 `NextToken` + `MaxResults`（上限 300）；金額一律按字串轉 `Decimal` 處理——這一點在第 2 篇對賬實戰裡吃過教訓，費用場景同樣適用。

### 2.2 一份自動化的月度成本報表

```python
from collections import defaultdict
from decimal import Decimal

from alibabacloud_bssopenapi20171214.client import Client as BssClient
from alibabacloud_bssopenapi20171214.models import DescribeInstanceBillRequest
from alibabacloud_tea_openapi.models import Config

client = BssClient(Config(
    access_key_id=ak, access_key_secret=sk,
    endpoint="business.ap-southeast-1.aliyuncs.com",
))

by_product = defaultdict(Decimal)
next_token = None
while True:
    resp = client.describe_instance_bill(DescribeInstanceBillRequest(
        billing_cycle="2026-09",
        is_billing_item=False,
        max_results=300,
        next_token=next_token,
    )).body
    for item in resp.data.items:
        by_product[item.product_code] += Decimal(item.pretax_amount or "0")
    next_token = resp.data.next_token
    if not next_token:
        break

for code, amt in sorted(by_product.items(), key=lambda kv: -kv[1]):
    print(f"{code:24s} {amt:>12.2f}")
```

把這段排成每月 3 號的定時任務，輸出 CSV 發給負責人，「看得見」就完成了八成。要進一步按「應用/部門」歸集，就用實例 ID 去關聯標籤（見下節），在報表側做 join 即可。

### 2.3 標籤：成本歸集的前提

建議三個標籤起步，不要貪多：

| 標籤 | 取值示例 | 用途 |
|------|----------|------|
| `env` | prod / staging / dev | 區分生產與非生產成本 |
| `app` | pos、mall、erp | 按應用歸集，算單位成本 |
| `owner` | 團隊或負責人 | 賬單有人認領 |

配套兩條紀律：新資源無標籤不許過（用巡檢腳本或配置審計規則檢查）；每月報表單獨列一欄「未打標籤資源」，限期認領。**未打標籤 = 成本黑洞**，這條比任何優化技巧都重要。

## 三、分得清：從總賬到單位成本

拿到明細後做三層聚合：按產品（錢花在哪類資源）、按標籤（錢花在哪個應用）、按訂閱類型（預付還是後付、結構是否健康）。

比總額更有用的是**單位成本**：每筆訂單的雲成本、每家門店每月的雲成本、每個活躍用戶的雲成本。總額漲 20% 可能是業務漲 20%（好事），單位成本漲 20% 才是問題。小團隊沒有預算系統沒關係，一張月度試算表加上上面三個維度就夠了。

另一個澳門特色：內部報表把 USD 按**當月固定匯率**折成 MOP，並把「匯率差」與「成本差」分開列示，避免把匯率波動誤讀成成本失控（匯率表的做法沿用第 2 篇的實踐）。

## 四、優得動：計費模型對齊工作負載

成本優化最大的槓桿不是砍規格，而是**讓計費模型匹配工作負載特徵**：

![按工作負載選擇計費模型](/images/sme-cost-billing-tree.png)

幾個補充判斷：

- **節省計劃 vs 包年包月**：節省計劃適合「算力基線穩定但規格將來可能換」的場景（跨規格族抵扣），包年包月適合「明確不會動」的底座。兩者每月看兩個指標：覆蓋率（抵了多少基線）與利用率（買的額度用了多少）——覆蓋高但利用低，說明買錯了範圍。
- **定時啟停是最容易拿的錢**：辦公與測試類負載用 OOS（運維編排服務）排程，夜間與週末自動 Stop、上班前 Start，只此一項通常就能省下該部分過半費用，且一次配置長期生效。
- **Right-sizing 用數據說話**：拉 CloudMonitor 近 30 天 CPU/內存的 P95，長期低於 20% 的就是降配候選；RDS 存儲自動擴容是單向的、降配需要窗口，開之前想清楚。
- **存儲與流量是沉默的大戶**：OSS 生命週期規則清掉未完成的分片上傳、30 天轉低頻、90 天轉歸檔；快照策略設保留天數；公網從「按固定帶寬」改為按流量或共享帶寬包；靜態資源交給 CDN；未綁定資源的 EIP 也在計費，巡檢釋放。

## 五、防得住：把成本變成工程約束

優化做一次會回彈，防得住才算治理。四件事：

1. **預算與告警**：按賬號或標籤設月度預算，在 50% / 80% / 100% 觸點通知負責人；異常日賬單（如環比突增）同樣設告警。
2. **規格約束**：大規格實例的購買在流程上需管理員確認，或用 RAM 策略限制可購規格族——不是不信任，是讓「花大錢」變成一個有意識的動作。
3. **月度成本例會 30 分鐘**：只看三個數——總額對預算、環比增長 Top 5、未打標籤資源清單。例會短，才開得下去。
4. **上線檢查單加一項「成本」**：新服務上線必須申報預估月成本與標籤，像安全檢查一樣成為 release 的一部分。

## 六、效果示意（綜合案例）

以下為綜合項目經驗的**示意區間**，實際以巡檢結果為準：

| 措施 | 典型節省（該部分費用） |
|------|------------------------|
| 非生產定時啟停 | 50–70% |
| 實例/RDS 降配 | 20–40% |
| 基線轉節省計劃/包年包月 | 20–50% |
| 存儲生命週期與快照清理 | 30–60% |
| 帶寬/流量模型調整 + CDN | 10–40% |

重點不在單項數字，而在節奏：第一個月通常能拿到最大的一筆（閒置與計費模型），之後每月例會維持增量，成本就從「年底嚇一跳」變成「每月一個數」。

## 七、避坑清單

| 坑 | 說明與對策 |
|----|-----------|
| 賬單 API 時效 | 當月數據多次修正，結算口徑用次月初終版；監控口徑可容忍延遲 |
| 節省計劃買而不用 | 覆蓋率高但利用率低 = 購買範圍錯；每月復核，到期前再續 |
| 搶占式實例被回收 | 必須有 checkpoint 與重試設計；狀態類服務不要用 |
| 快照與鏡像沉默增長 | 自動快照策略 + 保留天數；每月巡檢 Top 增長項 |
| 跨地域流量另計 | 跨地域複製、互聯流量單獨計費，架構評審時就要算進去 |
| USD 匯率干擾 | 內部報表用當月固定匯率，匯率差與成本差分開列示 |
| 標籤治理半途而廢 | 未打標籤資源每月列榜認領；巡檢 + 告警雙保險 |
| 只看總額不看結構 | 總額持平但存儲/流量結構惡化會被掩蓋；按維度看趨勢 |
| 新版 SDK 命名不一致 | `alibabacloud_*` 系列方法名與響應屬性命名不統一，以產品元數據為準，不要憑慣例猜 |

## 八、總結

三句話收束這篇：

1. **把賬單變成可查詢的數據資產**——API 拉明細、定時出報表，是一切治理的起點；
2. **讓計費模型對齊工作負載**——最大的槓桿在選型（訂閱/節省計劃/搶占/Serverless/定時啟停），不在砍規格；
3. **把成本變成月度節奏**——標籤、預算、例會、上線檢查單，讓治理自己長在流程裡。

小團隊不需要 FinOps 平台，需要的是把上面四步跑成習慣。
